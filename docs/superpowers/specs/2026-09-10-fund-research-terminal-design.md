# 个人公募基金研究终端设计

日期：2026-09-10

## 1. 项目定义

本项目是一个运行在用户电脑上的个人公募基金研究终端。它通过公开数据源收集基金净值、指数、持仓、规模和基金经理等信息，经过本地校验和计算后，以网页形式展示基金的历史业绩、风险及持仓结构。

首个完整研究案例为博时新兴成长混合（050009），但数据模型和搜索入口支持其他开放式公募基金。用户无需 Wind 终端、WindPy 权限、云服务器或编程经验即可运行最终产品。

本工具只提供数据整理和统计分析，不预测未来收益，不输出“买入”“卖出”或目标收益等投资建议。

## 2. 用户与使用场景

目标用户是没有编程经验、希望独立研究公募基金的个人投资者。第一版只有一个本地用户，不设账户、权限或云同步。

核心使用流程：

1. 用户在本机启动应用，浏览器打开本地页面。
2. 用户输入基金名称或代码，例如 `050009`。
3. 应用从本地数据库读取已校验的数据并打开基金研究页。
4. 若该基金从未下载过数据，应用提示并执行首次下载。
5. 用户点击“更新数据”，应用只补充上次成功更新之后的新数据。
6. 页面展示数据日期、来源和更新状态；更新失败时继续展示上一次成功的数据。

## 3. 第一版范围

### 3.1 包含的功能

- 通过基金代码或名称搜索开放式公募基金。
- 展示基金名称、代码、类型、管理人、基金经理、风险等级、投资范围及官方业绩比较基准文字。
- 展示单位净值、累计净值、复权净值和历史净值曲线。
- 展示近 1 月、3 月、6 月、1 年、3 年、5 年、成立以来及各自然年度收益。
- 计算并展示年化收益、年化波动率、最大回撤、最大回撤区间和夏普比率。
- 将基金走势与沪深300进行对比，并计算同期超额收益。
- 展示最近已披露报告期的基金规模、资产配置、行业配置和前十大持仓。
- 展示最近基金经理及其任职起始日期；仅在数据足够时展示任职期收益。
- 展示申购费、赎回费、管理费和托管费等已取得的官方费率信息。
- 提供首次下载、增量更新、更新时间及失败状态提示。

### 3.2 不包含的功能

- 盘中估值、实时行情和价格提醒。
- 账户交易、申购赎回或券商连接。
- 用户实际持仓、成本、盈亏及个人信息管理。
- 新闻、研报、社区内容和 AI 预测。
- 自动选基、组合优化、策略回测和收益排名。
- 公网部署、多用户、登录、移动端原生应用和后台定时任务。
- 第一版不复原 050009 的完整复合业绩基准曲线，只展示官方基准文字并以沪深300作为可计算的市场参照。

## 4. 050009 的基准事实

首个验收基金为博时新兴成长混合，代码 `050009`。基金管理人为博时基金管理有限公司，基金合同生效日为 2007-07-06，类型为偏股混合型。

官方产品资料中列示的业绩比较基准为：

> 沪深300指数收益率 × 80% ＋ 中国债券总指数收益率 × 20%

第一版在页面明确展示该文字和官方资料链接。由于免费数据源中的中国债券总指数历史序列稳定性尚不能保证，第一版不把沪深300曲线冒充官方复合基准。后续只有在取得连续、可追溯的债券指数数据后，才增加完整复合基准曲线。

官方参考资料：

- 博时基金产品资料概要：<https://www.bosera.com/common/downloadFile.do?fileId=11F8C3AC19E096C5A00DA3C39887ADE1>
- AKShare 项目及使用声明：<https://github.com/akfamily/akshare>

## 5. 页面设计

应用采用单个基金研究页加页内标签导航，避免为第一版建立复杂的多层菜单。

### 5.1 顶部区域

- 应用名称。
- 基金名称或代码搜索框。
- “更新数据”按钮。
- 最近成功更新日期和当前更新状态。

### 5.2 基金摘要

- 基金名称、代码、基金类型和管理人。
- 最新单位净值及其净值日期。
- 近一年收益、最大回撤、最近基金规模四张摘要卡。
- 对任何非当日数据明确显示日期，不使用“实时”字样。

### 5.3 页内标签

1. **总览**：基金与沪深300走势、关键收益风险指标、年度收益、最近资产配置及前十大持仓摘要。
2. **业绩与风险**：不同区间收益、年化收益、年化波动、夏普比率、最大回撤曲线及回撤区间。
3. **持仓分析**：资产配置、行业分布、前十大持仓、持仓集中度以及各数据的报告期。
4. **基金经理**：经理姓名、任职起始日及数据足够时的任职期表现。
5. **资料与费率**：投资目标、投资范围、官方业绩比较基准、风险等级、费率和官方文件链接。

每张图和每个持仓模块都显示数据日期或报告期。页面底部固定显示“数据与统计仅供个人研究，过往表现不代表未来收益”。

## 6. 技术架构

第一版采用单机、单进程、单语言架构：

- Python 3.11 作为运行环境。
- Streamlit 负责本地网页、输入控件、页面导航和状态提示。
- AKShare 作为公开金融数据的接入适配器。
- SQLite 保存基金、净值、指数、持仓、基金经理和更新日志。
- pandas 与 NumPy 负责清洗、日期对齐和指标计算。
- Plotly 负责净值、回撤、年度收益和持仓图表。
- Python 标准库 `sqlite3` 负责数据库访问；第一版不引入 ORM、消息队列或独立后端服务。

逻辑分为五层：

1. **数据源适配器**：调用外部接口，并把不同返回格式转换为项目内部字段。
2. **数据校验器**：检查必要字段、类型、日期顺序、重复记录、空值和合理范围。
3. **数据仓库**：使用 SQLite 事务写入和读取数据。
4. **分析引擎**：只接收已校验的净值与指数序列，计算收益和风险指标。
5. **Streamlit 页面**：读取仓库与分析结果，展示状态、表格和图表，不直接调用外部接口。

这种边界允许 AKShare 某个接口变化时只修改数据源适配器，不修改指标公式和页面。

## 8. 数据来源与优先级

### 8.1 结构化公开数据

AKShare 接口用于取得：

- 开放式基金代码、名称和类型目录。
- 单位净值、累计净值、净值日期、日增长率和分红信息。
- 沪深300历史指数数据。
- 基金持仓、行业或资产配置、规模及基金经理等公开信息。

AKShare 是接入工具而不是数据准确性的最终保证。其公开接口可能因上游网页变化而失效，因此每类数据必须经过适配器和校验器，不能让页面直接依赖 AKShare 的原始列名。

### 8.2 官方披露资料

博时基金发布的产品资料概要、招募说明书和定期报告用于核对 050009 的投资范围、业绩比较基准、风险说明和费率。第一版把核对后的文字及链接保存在版本控制内，不自动解析 PDF。

### 8.3 数据时间属性

- 净值属于开放日发布数据，不承诺固定在收盘时刻可用。
- 持仓、行业配置、规模和部分经理信息以最近公开报告为准，不是每日实时信息。
- 页面同时展示“数据日期”和“本地抓取时间”，两者不得混用。

## 9. 本地数据模型

SQLite 至少包含以下表：

- `funds`：基金代码、名称、类型、管理人、风险等级、官方基准文字、官方来源链接。
- `nav_history`：基金代码、净值日期、单位净值、累计净值、每份分红、复权净值、数据来源、抓取时间；基金代码与净值日期组成唯一键。
- `index_history`：指数代码、交易日期、收盘点位、数据来源、抓取时间；指数代码与交易日期组成唯一键。
- `fund_snapshots`：基金代码、报告期、基金规模及来源。
- `allocations`：基金代码、报告期、配置维度（资产或行业）、配置名称、占基金净值比例及来源。
- `holdings`：基金代码、报告期、排名、证券代码、证券名称、占基金净值比例及来源。
- `manager_tenures`：基金代码、基金经理、任职起始日、任职结束日及来源。
- `fee_schedules`：基金代码、费用类型、适用金额或持有期限下限、上限、费率或固定金额、币种及来源。
- `update_runs`：更新对象、开始和结束时间、状态、成功写入行数、最后数据日期和错误摘要。

所有日期以 ISO `YYYY-MM-DD` 字符串存储。百分比在数据库中保存为小数，例如 5% 保存为 `0.05`，只在页面格式化为百分号。

## 10. 更新流程与失败保护

### 10.1 首次下载

当用户首次打开一个本地没有数据的基金时：

1. 页面显示需要下载历史数据，并等待用户确认。
2. 更新服务依次取得基金资料、净值、沪深300、基金快照、持仓和经理数据。
3. 每类数据在内存中完成字段映射和校验。
4. 校验通过后使用 SQLite 事务写入；某一数据集失败不会写入该数据集的半成品。
5. 核心净值数据成功后即可打开研究页；持仓等次要数据失败时显示独立警告。

### 10.2 增量更新

用户点击“更新数据”后，服务读取各表的最后数据日期，只请求或保留更晚的数据，并通过唯一键执行幂等写入。重复点击不会制造重复记录。

### 10.3 异常行为

- 网络超时：记录失败状态，展示本地旧数据和最后成功时间。
- 外部字段改变：校验失败，不覆盖现有数据，并提示“数据接口格式发生变化”。
- 返回空数据：视为失败或无新增数据，不能用空集合清除历史表。
- 单日缺失：图表保留缺口，不以零值填充。
- 指标所需样本不足：显示“样本不足”，不显示误导性的零值。
- 持仓报告过期：仍可展示，但必须突出报告期。

错误信息面向普通用户描述可采取的行动，例如“请稍后重试”；详细异常只写入本地日志，不把冗长堆栈展示在页面中。

## 11. 指标计算口径

### 11.1 复权净值与收益

收益指标优先使用包含现金分红影响的复权净值。若净值日 `t` 每份分红为 `D_t`，复权序列按下式递推：

```text
adjusted_nav_t = adjusted_nav_(t-1) × (unit_nav_t + D_t) / unit_nav_(t-1)
```

若分红信息不完整，则优先使用数据源提供且可校验的累计收益序列；两者都不可用时，受影响的收益和风险指标显示“数据不足”，不能直接使用未复权单位净值产生可能失真的长期收益。

区间起点不是净值发布日时，使用不晚于目标起点的最近一个净值日；终点使用不晚于页面数据日期的最近一个净值日。

区间收益：

```text
total_return = adjusted_nav_end / adjusted_nav_start - 1
```

样本覆盖至少 250 个有效净值日后才展示年化收益：

```text
annualized_return = (adjusted_nav_end / adjusted_nav_start) ^ (250 / return_observation_count) - 1
```

其中 `return_observation_count` 是首尾净值之间的有效日收益样本数，而不是自然日数。

### 11.2 年化波动率

先计算相邻净值日简单收益率。至少有 30 个日收益样本时展示：

```text
annualized_volatility = sample_std(daily_return) × sqrt(250)
```

样本标准差使用 `ddof=1`。

### 11.3 最大回撤

```text
drawdown_t = adjusted_nav_t / running_max(adjusted_nav) - 1
max_drawdown = min(drawdown_t)
```

同时记录形成最大回撤的历史高点日期和最低点日期。

### 11.4 夏普比率

第一版采用 0% 无风险利率并在页面注明：

```text
sharpe_ratio = mean(daily_return) / sample_std(daily_return) × sqrt(250)
```

至少有 30 个日收益样本且标准差大于零时才展示。

### 11.5 基准与超额收益

基金和沪深300按共同可用日期对齐。沪深300区间收益使用指数收盘点位计算：

```text
excess_return = fund_total_return - csi300_total_return
```

页面明确将沪深300标为“市场参照”，不标为 050009 的完整官方业绩比较基准。

### 11.6 持仓指标

持仓集中度等于最近报告期前十大持仓占基金净值比例之和。年度收益按自然年首末可用复权净值计算；当前未结束年份标记为“年初至今”。

## 12. 测试策略

### 12.1 单元测试

- 使用固定上涨、固定下跌、先涨后跌和零波动的人工净值序列验证收益、年化波动、最大回撤和夏普比率。
- 使用含现金分红的人工序列验证复权净值。
- 验证样本不足、日期重复、日期乱序、空值和标准差为零时的行为。
- 验证基金与指数日期不完全相同时的共同日期对齐。

### 12.2 数据与数据库测试

- 使用模拟的 AKShare 返回值测试外部列名到内部字段的映射。
- 缺少必要列时校验器必须拒绝数据。
- 使用临时 SQLite 数据库测试首次写入、增量写入、重复写入和事务回滚。
- 空响应或写入失败不能改变原有成功数据。

### 12.3 页面与验收测试

- 使用 Streamlit 的应用测试能力验证搜索、首次下载提示、更新状态和五个页内标签。
- 对 `050009` 执行一次可联网的人工验收：能搜索、下载并显示净值、收益、风险和最近持仓。
- 断开网络后再次打开 `050009`，页面必须继续显示本地旧数据并明确更新时间。
- 抽样对照博时官方公开资料中的基金名称、类型、基准文字和报告期。

联网烟雾测试不作为纯单元测试的硬依赖，避免上游暂时不可用导致本地公式测试失去价值。

## 13. 完成标准

第一版只有同时满足以下条件才算完成：

1. 新用户能按照 README 在本机创建 Python 环境、安装依赖并启动应用。
2. 用户能通过名称或代码找到 `050009` 并打开研究页。
3. 页面能够展示最新已取得净值、历史曲线、区间收益、年化波动、最大回撤、夏普比率、沪深300参照及最近公开持仓。
4. 所有指标按本设计中的公式计算并通过固定样例测试。
5. 所有非每日数据展示报告期，所有页面展示最后成功更新时间。
6. “更新数据”执行增量、幂等写入。
7. 网络或外部字段异常不会破坏本地已有数据。
8. 页面不展示虚构数据，不把缺失值显示为零，不产生投资建议。

## 14. 已知风险与后续扩展

公开数据接口存在字段变化、访问限制和短期不可用风险。第一版通过适配器隔离、字段校验、本地缓存、事务写入和更新时间提示降低风险，但不承诺公开数据达到商业金融终端的数据服务等级。

后续版本可在第一版稳定后依次考虑：

1. 引入稳定的中国债券总指数数据，计算 050009 完整官方复合基准。
2. 增加同类基金比较和风险收益散点图。
3. 增加基金关注列表和本地研究笔记。
4. 使用 macOS `launchd` 实现可选的每日后台更新。
5. 在用户明确需要并接受部署成本后，再考虑云端私人访问。

上述扩展均不属于第一版交付范围。
